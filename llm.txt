# PromptHub — Project Context for LLM Assistants

> For external LLM tools (Perplexity, etc.) that read project files through
> Desktop Commander or similar. A self-contained snapshot; the authoritative
> developer contract is AGENTS.md.
>
> Last updated: 2026-11-21

## What this project is

PromptHub is a local MCP (Model Context Protocol) router for macOS on
localhost:9090:

- **MCP routing**: one endpoint proxies the servers in
  `app/configs/mcp-servers.json` (context7, desktop-commander,
  sequential-thinking, memory, duckduckgo, obsidian-mcp-tools,
  perplexity-comet, chrome-devtools-mcp, knowledge-to-action). The Node bridge
  `mcps/prompthub-bridge.js` aggregates them for clients.
- **Server-side client profiles**: model, tool disclosure, and privacy level
  per client in `app/configs/enhancement-rules.json`.
- **Prompt enhancement**: a local LLM rewrites prompts per client.
- **OpenAI-compatible proxy**: `/v1/chat/completions`, `/v1/responses`,
  `/v1/models` with bearer auth.
- **Resilience**: circuit breakers, L1/L2 cache, OpenRouter free-tier fallback
  for clients that allow it.

## Tech stack

- Python 3.11+, FastAPI, Pydantic, uvicorn, httpx, aiosqlite, FastMCP
- Node.js stdio bridge for MCP clients
- Local LLM: LM Studio (port 1234), OpenAI-compatible API
- HTMX + Jinja2 dashboard at `/dashboard`
- SQLite state under `~/.prompthub/`

## Clients

Configured in enhancement-rules.json: claude-desktop, claude-code, codex,
vscode, raycast, perplexity, cursor, comfyui, open-webui, lm-studio, opencode.
Each client uses the same bridge entry with its own `CLIENT_NAME`.

## Key design decisions

- Privacy boundary: `local_only` prompts never leave localhost; `free_ok`/`any`
  may fall back to OpenRouter (ADR-007).
- Task-specific models per client via model profiles (ADR-008).
- Progressive tool disclosure cuts initial tool context by ~80%.
- Bridge strips verbose tool-schema fields (~67% smaller).
- Enhancement input capped at 4,096 tokens.
